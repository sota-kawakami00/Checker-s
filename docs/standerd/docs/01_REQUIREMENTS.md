## 2. 主要ユースケースフロー

### UC-01: 標準査定フロー（正常系）

```
1. ホーム →「新規査定」
2. 車検証撮影 → OCR自動入力 → 補正・装備入力（SCREEN_VEHICLE_INFO）
3. ガイド付き12アングル撮影。各撮影直後に品質AI判定（SCREEN_CAMERA）
4. 傷・気になる箇所を追加撮影（部位タグ付け）
5. 「AI査定を実行」→ 進行状況表示（〜60秒）
6. 査定結果表示: 価格 + 根拠内訳 + 修復歴 + 市場比較 + 査定漏れ診断
7. 未確認項目を現車確認 → チェック
8. 必要なら価格調整（理由必須）→「査定を確定」
9. PDF生成 → 顧客に提示/共有
```

### UC-02: オフライン査定フロー

```
1〜4は完全オフラインで実行可能（下書き保存）
5の時点で圏外 → 「オフラインです。通信回復後に自動でAI査定を実行します」
→ オフラインキューに登録 → 回復検知 → 自動実行 → プッシュ通知
```

### UC-03: 修復歴疑い検出フロー

```
AI査定結果で repairProbability >= 0.5
→ 結果画面に警告カード（該当画像 + 根拠のヒートマップ的注釈）
→ スタッフに現車確認を要求（確認チェックなしでは確定不可）
→ 確認結果（修復歴あり/なし/不明）を記録 → 価格へ反映（再計算）
```

## 3. 業務ルール（ドメインルール）

| ID | ルール |
|---|---|
| BR-01 | 査定価格は1万円単位に丸める（切り捨て） |
| BR-02 | 加減点内訳の合計 + 基準価格 = 査定価格 が常に成立すること（クライアント検証、破綻時はAIエラー扱い） |
| BR-03 | AI信頼度 < 60% の査定は確定不可（manager承認で例外可） |
| BR-04 | 修復歴「あり」確定時は、修復歴ありの相場テーブルで再計算する |
| BR-05 | 査定の有効期限は7日間。期限切れは再査定を促す |
| BR-06 | 確定済み査定の価格変更は manager 権限のみ。変更履歴を全件保存 |

## 4. 非機能要件

| ID | 分類 | 要件 |
|---|---|---|
| NFR-01 | 性能 | 写真品質判定: 撮影後1.5秒以内（p95） |
| NFR-02 | 性能 | AI査定: リクエスト送信→結果受信 60秒以内（p95）。30秒超で進捗メッセージ切替 |
| NFR-03 | 性能 | 履歴一覧: 1000件でも初期表示1秒以内（ページング50件） |
| NFR-04 | 可用性 | オフラインで撮影・入力・下書きが完結。データ消失ゼロ |
| NFR-05 | 同期 | オンライン復帰後60秒以内に自動同期開始。競合はサーバー優先+ローカル退避 |
| NFR-06 | セキュリティ | `07_SECURITY.md` 全項目。特にナンバー/顔マスキングはアップロード前必須 |
| NFR-07 | プライバシー | 顧客個人情報はGeminiに送らない。査定に不要なEXIF（GPS）は送信前に除去 |
| NFR-08 | 信頼性 | クラッシュフリー率 99.8%。Crashlytics導入 |
| NFR-09 | 保守性 | Swift Package分割・DI・protocolモックでユニットテストカバレッジ 70%以上（Service/ViewModel） |
| NFR-10 | アクセシビリティ | Dynamic Type（〜xxxLarge）、VoiceOver、コントラスト比4.5:1以上 |
| NFR-11 | 国際化 | 文言は全て xcstrings。v1は日本語のみだが構造上多言語可能に |
| NFR-12 | コスト | Gemini呼び出しは1査定あたり定義された上限トークン以内。Functions側でレート制御 |
